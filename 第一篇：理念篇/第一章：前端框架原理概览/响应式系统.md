这张图描述的是 **React 中 useState 和 useEffect 的订阅发布关系**。

可以把它理解成：

> **state 是消息发布者，effect 是消息订阅者。**
>
> state 发生变化 → 通知订阅它的 effect → effect 执行副作用代码。

---

## 1. useState 里面有什么？

假设：

```jsx
const [count, setCount] = useState(0);
```

React 内部可以理解成：

```
useState(count)
      |
      ↓
   state对象
      |
      ↓
   subs 集合
```

图中的：

```
useState 1
 └── subs1
```

表示：

> 这个 state 保存了一个订阅列表。

比如：

```js
subs1 = [effect1, effect2, effect3];
```

意思：

> 谁关心 count 的变化，就放进 subs1。

---

## 2. useEffect 创建了什么？

代码：

```jsx
useEffect(() => {
  console.log(count);
}, [count]);
```

React 内部会创建一个 effect 对象：

```js
const effect = {
  execute() {
    console.log(count);
  },

  deps: new Set(),
};
```

对应图：

```
useEffect 1

    effect1
       |
       |
   ┌────────┐
   │execute │
   └────────┘

   ┌────────┐
   │ deps   │
   └────────┘
```

---

## 3. deps 是干什么的？

重点：

```
effect
  |
 deps
  |
 subs1
```

表示：

> 这个 effect 依赖哪些 state。

例如：

```jsx
useEffect(() => {
  console.log(count);
}, [count]);
```

那么：

```
effect1
   |
   deps
   |
   count对应的subs
```

关系：

```
count state
     |
     |
   subs1
     |
     |
 effect1
```

意思：

> count 变化，需要执行 effect1。

---

## 4. 初始化的时候发生什么？

执行：

```jsx
useEffect(() => {
  console.log(count);
}, [count]);
```

第一次：

React 发现：

```
effect1 使用了 count
```

于是建立双向关系：

### state 记录 effect

```
count
 |
 subs1
 |
 effect1
```

表示：

> count 变化通知 effect1

---

### effect 记录 state

```
effect1
 |
 deps
 |
 subs1
```

表示：

> effect1 依赖 count

所以图里面有两个方向：

---

### 方向1：state → effect

实线：

```
useState
   |
 subs1
   |
 effect1
```

作用：

> 发布通知

---

### 方向2：effect → state

虚线：

```
effect1
    |
   deps
    |
  subs1
```

作用：

> 记录依赖关系

---

# 5. 当 setState 执行时

例如：

```jsx
setCount(10);
```

发生：

```
count改变
   |
   ↓
找到 subs1
   |
   ↓
里面有哪些effect?
   |
   ↓
执行 effect.execute()
```

类似：

```js
subs1.forEach((effect) => {
  effect.execute();
});
```

于是：

```js
console.log(count);
```

重新执行。

---

# 6. 为什么需要 deps？

因为一个 effect 可能依赖多个 state。

例如：

```jsx
useEffect(() => {
  console.log(user.name, count);
}, [user, count]);
```

关系：

```
          user state
              |
            subs1
              |
              |
          effect1
              |
              |
            deps
              |
              |
          subs2
              |
            count state
```

effect1 同时订阅：

```
user
count
```

所以：

```
effect1.deps = {
    user.subs,
    count.subs
}
```

---

# 7. 和 Vue 响应式比较

其实和 Vue3 很像：

Vue：

```
reactive对象
      |
    dep
      |
   effect
```

React：

```
useState
      |
    subs
      |
   useEffect
```

本质都是：

```
数据
 |
依赖收集
 |
副作用函数
 |
数据变化
 |
重新执行
```

---

## 一句话总结这张图

> **useState 里面的 subs 是“订阅者名单”，保存哪些 useEffect 依赖这个 state；useEffect 里面的 deps 是“我订阅了哪些 state”。state 改变时，通过 subs 找到 effect，然后调用 effect.execute() 执行副作用。**

也就是一个简化版的发布订阅系统：

```
          发布
state  ------------> effect
          通知


effect ------------> state
          记录依赖
```

React Hooks 的响应式原理核心就是这套关系。
